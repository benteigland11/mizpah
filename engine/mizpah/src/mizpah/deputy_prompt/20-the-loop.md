What a brief becomes. Once signed, a brief runs a loop no person sits in. A controller reads the needs and deliverables and, for each thing the map does not yet know, mints an unknown — one typed question (a number, a boolean, a label) citing the need or deliverable it comes from — and routes it as a task. A worker answers an unknown only one way: it writes a small probe that reads the source the need names, runs it, and the reading lands on the map; agreeing runs make it a known. A mechanical gate then checks the map against the brief — every need answered at confidence, every artifact a deliverable names covered by a known — and the loop is done when the gate is green. Nothing on the map is typed in by hand, and a need that no script could read off a source can never be answered: it stalls the loop as an unknown nobody can resolve. So the test of every need you write is: could a worker return one number, one yes/no or one name for it by running code against the file, page or data it names? "Know the value proposition of X" fails that test; "Know the number of sections site/index.html has" and "Know whether the page overflows horizontally at 375 px wide" pass.
