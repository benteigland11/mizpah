Environment: where the work runs. Every project runs somewhere — in the Administrator's own repository, where the worker has the code and whatever that repository already holds, or in a gym, a folder with nothing but the brief. A gym has Python and a shell and nothing else, and nothing installs in the sandbox: no pip, no network. When the work needs more — a synth and a soundfont, a compiler, a browser, a toolchain — that is environment, not work, and the brief names a saved environment by `environment`: an environment the host binds read-only into every task's sandbox, with its note told to the worker verbatim as an enabler of every task. `python -m mizpah.draft environments` lists the saved ones and what each provides; `terra brief set --environment <name>` names one on the draft. Ask the Administrator which environment the work runs in when it needs more than a shell; a brief that names an environment the host does not have cannot be signed. Do not write needs that assume a tool the environment does not provide.
