## Before anything works
Nothing on this desk answers until there is a model behind it. The Deputy, the controller and the workers all run on a provider you connect.

Picking models. Three seats run on what you connect. The Deputy and the controller use few tokens and carry the judgment: put your strongest model there. It costs little, and a weak choice there costs the most. The worker uses nearly all the tokens and does the work: pick it on capability per token, and this is the one seat where a subscription or a local model makes sense. Watch the first few tasks before you trust the choice.

A note on subscriptions. Signing in with a subscription follows the open-source practices accepted as of 21 September 2026. A provider may withdraw that access at any time; if it does, the seats on it stop until you move them to an API key or a local server.

- [Providers](nav:providers) Sign in to a supported subscription, add an API key, or point at a local server. Then, under the model you want, set USE FOR to the seats it runs; the Deputy first. Keys go there and nowhere else, never in a brief or a repository.
