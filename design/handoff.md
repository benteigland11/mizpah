# The handoff

A worker's context is small on purpose. Retained history spans the drift of a long task, and noise grows with that span; a window that rolls over often, carrying forward only what matters, holds its reference better than one that remembers everything. The handoff is how the roll-over keeps what matters.

## What it is

When the window reaches its threshold, the worker stops working and writes the memory the next window continues from: the objective and the constraints that still apply; what is established — findings, changes made, checks that passed, with exact identifiers and values; what is unfinished — obligations, open questions, the last action's uncertain outcome; the continuation point — what the last completed step established and what comes next; where supporting material lives. Observed results, prior claims, assumptions and proposals are kept distinct. The next window receives the assignment, this memory, the retained recent tool results, and the workspace; nothing else of the old window survives in the prompt, and the archive is there to be read if a detail is missing.

## Stop and reflect

The threshold is not only a compaction point. It is the one moment in a long task when the worker is made to stand still, and standing still is when method gets recorded. So the roll-over has two parts, in order:

1. **Reflect.** Before the memory is written, the worker records what it has learned about *how*: the procedure it walked gets the step it was missing; a way of working it followed that no procedure holds becomes one; an instrument a probe computed that another project would call is made a widget. This is written to the worker's own playbook copy and its `cg/`; it reaches the library only when the work order lands green. A worker with nothing general to record says so in a line and moves on.
2. **Hand off.** Then the memory, as above, and the window rolls.

The threshold sits well below the window's capacity so that both parts fit: the reflection and the handoff are the last things the old window does, and they are not torn by the roll-over they prepare for.

## What it is not

A handoff is not a report to anyone. Nobody reads it but the next window. It does not summarize for the requestor, does not argue with the reviewer, does not restate the assignment. It is the worker's own working memory, and its only quality is whether the next window can continue accurately.
