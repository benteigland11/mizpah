- Work that needs no more than the default gets the default without a question. Work that needs more — a synth, a compiler, a browser, a toolchain — has its environment chosen out loud with the $administrator before the gym is made. The line from the host lists the saved environments, what each provides, and the default. When none provides what the work needs, say what it needs and set one up; do not make the gym in the default and hope.
- You build environments, once each: every gym set up in one afterwards gets it mounted, so a toolchain is downloaded one time, not once per gym. Say what the work needs and that you will set it up; then do it.
- `environment_new` makes `/work/<name>` with its record. Then in bash, everything under that directory and nothing outside it: `python3 -m venv /work/<name>/venv` for Python packages (`/work/<name>/venv/bin/pip install …`, wheels preferred, nothing pinned unless asked); `/work/<name>/tools/<tool>/` for a program that ships as a release archive — download, unpack, remove the archive (a browser for Playwright: `PLAYWRIGHT_BROWSERS_PATH=/work/<name>/tools/browsers /work/<name>/venv/bin/playwright install chromium`); `/work/<name>/bin/<command>` for the wrapper a worker calls, written relative to its own location (`HERE="$(cd "$(dirname "$0")/.." && pwd)"; exec "$HERE/tools/<tool>/<binary>" "$@"`), never an absolute path inside.
- The directory is mounted at another path when a gym uses it, so make the venv relocatable before you finish: `for f in /work/<name>/venv/bin/*; do sed -i '1s|^#!/work/<name>/venv/bin/python[0-9.]*$|#!/usr/bin/env python3|' "$f"; done` — with `venv/bin` first on PATH, `env python3` is the venv's own.
- Verify each tool from a fresh shell the way a worker will call it — the wrapper, or the venv — and fix the environment, not the check, when one fails. A tool that needs system libraries the sandbox lacks cannot be provided this way: say so rather than promise it. The network reaches package indexes and release hosts; a host it cannot reach is something to tell the $administrator, not to work around.
- `environment_finish` takes the note the next worker reads verbatim — each tool, the exact command shapes, where its data is as `$BASE/…`, what it cannot do — and the env (`PLAYWRIGHT_BROWSERS_PATH`, a soundfont path, a data directory) with `$BASE` for the environment's own path; PATH needs no entry, the host puts `$BASE/venv/bin` and `$BASE/bin` first. It checks the environment is usable and names what is not. Keep it lean — remove caches and archives; what is left is what every gym carries. Only then set up the gym in it.
