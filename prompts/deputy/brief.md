## Brief

The brief is the reference: the one document the whole loop is graded against, written before anything runs and signed by the $administrator. Once signed it runs a loop the $administrator does not sit in. The controller reads its needs and deliverables and, for each thing the map does not yet know, mints an unknown — one typed question citing the need or deliverable it comes from — and routes it as a work order. The worker answers an unknown one way only: a probe that reads the source, a run, a reading on the map; agreeing runs make it a known. The gate then checks the map against the brief — every need answered at confidence, every artifact a deliverable names covered by a known — and the work is done when the gate is green. Nothing on the map is typed in by hand: a need is met only through readings taken off a file, a page, data or an artifact. So a need must be about something a worker could read. A need about nothing (pure taste, no source, no artifact) leaves the controller nothing to mint, and the loop stalls on it.

What each part means, as the loop reads it:

- **Title** — names the project and becomes the name of its map, where every reading lands. An address, not a label; a few words.
- **Mission** — one or two sentences of context: what is built or found out, and how it is proved. The controller reads it on every step; nothing mechanical hangs on it.
- **Needs** (need:1, need:2 …) — what is needed from this work, one need per entry, in the requestor's words. A need is not a measurement: the controller turns it into the readings that answer it, one unknown at a time, citing the need by number. It is met when the unknowns citing it are knowns at confidence; owed while one is open; uncovered when nothing cites it. Each need is one thing, concrete enough that a controller could say what would have to be true for it to be met — the file, page, data or artifact it is about, when there is one — with the how left to the loop. Needs are cited by number: removing one renumbers the rest. A need that cannot be met without an instrument the project lacks names that enabler's id in parentheses at its end, and waits for it.
- **Deliverables** (deliverable:1 …) — the artifacts the worker builds: one artifact by path each (`site/index.html`, `report/design.md`), what it must contain, and the needs it draws on by number. Three things are mechanical. Every path the text names goes on a ledger — built, created by some unknown, or nobody builds it yet, which the controller must resolve. Every backticked term is a named thing that must appear in some unknown citing the deliverable — a command, a file, a section — so backticks are the deliverable's vocabulary, one unknown each: use them for what must each be checked, not for decoration. And a deliverable is met only when the unknowns citing it are resolved; one nothing measures is never checked.
- **Non-goals** (non-goal:1 …) — constraints on method, shown to the worker. One mechanic: a backticked term in a non-goal is a thing that must not be made; an unknown whose artifact contains it is refused. Written as ``No `framework`: the page is HTML and CSS by hand``. Non-goals are not measured; what must be proven absent is a need (``No requests to any URL outside site/``).
- **Enablers** — the instruments readings depend on, by id, title and path, needed through building to ready. Declared only when readings truly cannot be taken without one (a headless browser to read a rendered page; a decoder for a binary format); most briefs need none. The controller routes an enabler first, as a work order that builds it at its path or installs it from the library.
- **Phases** — for a brief too large for one map: ordered scopes owning needs and deliverables by number, routed one at a time, closed mechanically; a later phase may name an earlier known by id. A flat brief with a dozen needs runs as it is.
- **Budget** — `budget_points` is the total effort in the route's own unit: a work order costs few points when its method is known, more when a couple of options must be tried, most when several are explored; the controller spends them and cannot route past the total. `budget_notes` is one sentence for whoever reads the brief: the horizon and why.
